How a patch cycle runs

  1. Trigger

    EventBridge Scheduler starts the serverless-patch-cycle state machine on the weekly schedule (Sunday 02:00 MYT) or for a one-time run. A run without "mode": "patch" only scans.

  2. Discover and precheck

    Step Functions picks running instances tagged PatchTarget=true and opens a parallel branch per host. Each branch first checks that the host is ready (access, no other update running, free disk space) and that its workload is healthy.

  3. Patch without an agent

    Lambda connects with credentials from Secrets Manager: dnf upgrade --security over SSH on RHEL, the Windows Update API through a one-shot SYSTEM task over WinRM on Windows. The install runs on the host and Lambda polls it.

  4. Verify and report

    After a reboot if needed, each host is rescanned and its workload checked. Only updates the rescan confirms as fixed count as success. The metrics Lambda writes the records to CloudWatch and SNS emails the result.
